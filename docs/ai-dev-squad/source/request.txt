A typical feature should follow this workflow:
1. Ayoube creates or refines the Jira story, establishes priorities, and defines acceptance criteria.
2. Reda prepares UX/UI specifications or visual assets when the feature needs them.
3. Walid designs the architecture, implements the feature, and performs developer-level checks.
4. Annas tests the changes, reviews integration, verifies CI/CD, and reports defects.
5. Ayoube records the outcome, updates Jira, and plans the next task after the appropriate approvals.
Each agent should know when to involve another agent. They should never silently overwrite one another's work.
2. Tools and access strategy
I recommend giving each agent broad capability but narrowly scoped permissions. Full computer access should mean the ability to work in the right folders and apps, not unrestricted permission to delete files, push changes, or publish content.
Agent	Priority tools and integrations
Ayoube	Jira, Confluence, Google Calendar, Gmail, Google Drive, scheduled tasks
Walid	Codex, Git/GitHub, VS Code, IntelliJ, terminal, Docker, databases, project repositories
Annas	Git/GitHub, CI/CD logs, Postman/Apidog, Playwright, Jest, JUnit, Maven, test databases
Reda	Figma, Canva, image generation, video editing tools, design assets, frontend preview

Some of these connectors are already available in this environment, including Atlassian, Figma, Canva, Gmail, Google Calendar, and Google Drive. GitHub and local file access still need to be verified and configured for the relevant workflow.

Important implementation detail: ChatGPT Work can use connected apps and a cloud browser, and its desktop version can work with authorized local folders. Actual computer access is limited by the capabilities and permissions of the session. Dedicated Workspace Agents are also available in eligible Business and Enterprise workspaces, but creating four named agent personas in a Work prompt does not automatically provision four independent persistent agents.
