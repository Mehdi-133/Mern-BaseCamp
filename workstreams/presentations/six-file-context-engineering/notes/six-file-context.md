# 🧠 Six-file context — quick review

> 🟡 **In progress** — materials prepared; learner explanation and exercise pending.
>
> 🧠 **Big idea:** brief the AI, scope a change, check its work, and preserve the evidence.

## 🔑 Key points

- The supplied JavaScript Mastery method has six files: product overview, architecture, UI context, code standards, AI workflow rules and progress tracker.
- An entry file directs the assistant to those documents. A separate feature spec describes one immediate task.
- Six is an adaptable organization choice. Accurate, relevant content matters more than file count.
- The engineer reviews assumptions and changes, chooses checks, and remains responsible for acceptance.

## 📖 Eloquent JavaScript foundation

- **Chapter 8 — Bugs and Errors, printed pp. 135–136**, inspected in the local PDF.
- Automated tests compare executable behavior with expectations; debugging finds why behavior differs.
- The book does not teach this six-file method; it supports the verification step.

## 🧩 MERN connection

- Record MongoDB relationships, Express request contracts, React interaction states and Node.js verification commands when relevant to the task.
- A documented intention is not evidence that any layer works.

## ⚠️ Common trap

- Treating generated docs or a “complete” label as proof. Require actual checks, and mark unrun checks explicitly.

## 🌐 Web culture

- Reuse authoritative README files, design decisions and issue criteria instead of duplicating them.
- Tool loading conventions differ. A file on disk must be brought into the assistant's working context to help.
