# 🎤 Workshop proposal — AI with Context

> 🟡 Proposed format: 60 minutes, beginner/intermediate developers, two facilitators. Timing and colleague roles are suggestions, not a confirmed school assignment.

## 🎯 What participants should leave able to do

Explain the six files, write one small task specification, question an AI-generated change, and record what was actually checked.

## 🤝 Suggested split

| Time | Activity | Facilitator |
| --- | --- | --- |
| 0–5 min | Ask: “What does AI need to know about a project?” Show the problem of missing constraints | Mehdi |
| 5–15 min | Explain the six-file visual and entry point; show one useful sentence per file | Colleague |
| 15–25 min | Convert a vague feature into a scoped specification together | Both |
| 25–40 min | Compare equivalent demo sessions; inspect differences and run checks | Mehdi drives, colleague reviews |
| 40–50 min | Pairs complete the three-question exercise | Both support |
| 50–60 min | Debrief, explain mixed research evidence, answer questions and collect one takeaway | Colleague leads, Mehdi recaps |

Total: **60 minutes**. Swap roles to suit your strengths. Each person should understand both the context and verification stages.

## 🎬 Demo script

Use the lesson's tiny published-course filter in a disposable demo folder. Do not edit the team LMS for the workshop.

1. Prepare identical starter lists and acceptance checks for both sessions.
2. Session A gets a vague request. Observe its choices; do not claim it must fail.
3. Session B gets the relevant six-file briefing plus one clear specification.
4. Inspect the diff and execute mixed-list, empty-list and input-preservation checks.
5. Ask the audience to explain why each check matters.
6. Record actual outcomes and unknowns, including any extra context/review cost.

Use the same tool/model/settings, starter code, tool access and time allowance. Show supplied context openly. This is a teaching illustration, not a controlled performance benchmark. Have prepared illustrative outputs ready if accounts/network fail, and label them **illustrative**, never live evidence.

## 🗣️ Opening you can say

“Today we will learn how to brief an AI coding assistant like a teammate. We will define the product, architecture, code rules, workflow, UI and current progress. Then we will ask for one small change and check whether it really works.”
